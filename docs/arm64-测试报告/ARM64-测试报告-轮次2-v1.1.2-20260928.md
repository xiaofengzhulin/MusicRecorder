## 7. 步骤 5 / Q5 —— 模拟层播放器混跑：**通过（x86 模拟层）**

### 7.1 候选排查（为什么最后用 QQ音乐）

| 候选 | 架构 | SMTC 支持（二进制查证） | 结论 |
|---|---|---|---|
| 便携版 VLC 3.0.24 win64（本次下载） | **x64 `0x8664`**（模拟层） | **无**（全部 dll/exe 无 `SystemMediaTransportControls` 任何变体） | 可跨架构录音，但不发布 SMTC 会话 → 不能作为 Q5 的"会话识别"样本 |
| 本机既有 x64/x86 应用（Office x64、微信 x64、Epic、Steam、WPS x86、迅雷、学习通、唧唧Down…） | 模拟层 | 无 SMTC 引用 | 无一可用 |
| 系统媒体播放器 / 电影和电视 / Edge | ARM64 原生 | — | 不属于模拟层 |
| **QQ音乐 22.52**（本轮你安装） | **x86 `0x014C`**（模拟层） | **有 `SMTCFeature.dll`** | ✅ 采用 |
| PotPlayer（你安装，`PotPlayer-64 bit` 26.08.19.0） | **ARM64 `0xAA64`**（WOA 站点默认给 ARM64 包，**原生非模拟**） | 有（`MediaDB64.dll` 含 `SystemMediaTransportControls`、`PotPlayer64.dll` 含 `SMTC`） | 用于附加回归，不算模拟层样本 |

### 7.2 Q5 实测（QQ音乐，x86 模拟层）

`--selftest --seconds=8`（QQ音乐播放 `test-tone` 期间）：

```
[1] 会话列表: QQ音乐[QQMusic.exe] 播放中
    当前歌曲: test-tone /  / QQ音乐 / Playing / 00:08 of 00:30
    窗口标题兜底探测: test-tone - （QQ音乐）
[3] 录制时长 00:08.41｜峰值电平: 1.5%（解码峰值 1.6%）
    解码校验: 时长 00:08.47，声道 2，采样率 48000 → ✓ 录制与编码流程正常
exit code = 0
```

按轮次 2 判读标准「x64 模拟版播放器出现在 `[1] 会话列表` 且录音含其声音 → Q5 通过」：

- 会话识别：✅（**x86 模拟层进程**发布的 SMTC 会话被**原生 ARM64 进程**成功枚举，含标题/进度）
- 录音含其声音：✅ 峰值 **1.5% > 1%**（解码峰值 1.6%，量偏低是因 QQ音乐播放音量较低，非采集问题）
- 补充：模拟层为 **x86**（QQ音乐仅提供 32 位包）而非 x64 —— ARM64 上 x86 与 x64 同属模拟执行，跨架构结论等价，此处如实注明

### 7.3 附加：多播放器多会话并存（增强证据）

同时用 QQ音乐（x86 模拟层）+ PotPlayer（ARM64 原生）播放：

```
[1] 会话列表: QQ音乐[QQMusic.exe] 播放中 | PotPlayer[PotPlayerMini64.exe] 播放中
    窗口标题兜底探测: test-tone.mp3 - （PotPlayer）
[3] 峰值电平: 18.1%（解码峰值 18.1%）
```

→ **两种架构的第三方播放器会话可在同一列表共存**，环回同时录到两者声音；PotPlayer 的 SMTC 二进制引用也经实测生效。

### 7.4 附带发现（供工具方参考，非 MusicRecorder 缺陷）

- **VLC 3.x 不支持 SMTC**（二进制无 API）→ 用 VLC 测 Q5 会得到"会话列表为空"的**误判**；它只能验证录音链路（实测峰值 7.3% ✅）与窗口标题兜底（实测识别 `VLC` 且状态 `Playing` ✅）
- **WOA 上 PotPlayer 官方下载默认给 ARM64 版**（注册表名仍写 `PotPlayer-64 bit`）→ 想测"模拟层"必须另找 x86/x64 播放器
- 本机可复用的 Q5 标准样本：**QQ音乐（x86，含 SMTCFeature.dll）**
