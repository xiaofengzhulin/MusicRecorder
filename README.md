# MusicRecorder · 音乐内录工具

一款 Windows 桌面小工具：**读取音乐软件当前播放的歌曲 → 自动从头播放 → 内录系统声音 → 歌曲结束后自动停止 → 导出以「歌曲名-歌手」命名的 MP3。**

界面只有两部分：**上方选择导出路径，下方是「开始录制」按钮**。

## 一、功能

| 能力 | 说明 |
| --- | --- |
| 自动识别歌曲 | 通过 Windows 系统媒体会话（SMTC）读取 QQ音乐 / 网易云音乐 / 酷狗音乐 / 酷我 / 咪咕 / Spotify / PotPlayer 等正在播放的**歌曲名、歌手、专辑、播放进度**；同时开着多个播放器时，可在「目标播放器」里指定要录哪一个（界面显示与自动录制都遵守该选择） |
| 自动从头播放 | 点击开始录制后自动把当前歌曲**倒回 0:00**；按播放器声明的能力选择方案，确保真实生效（见下文） |
| **自动录制（单首）** | 勾选后，**在播放器里点播放就会自动倒回开头并开始录制这一首**，无需手动点「开始录制」；录完自动暂停播放器。**不追踪换歌**——一次播放只录一首 |
| **自动录制整张歌单** | 勾选后，点播放开始录制，**当前歌曲放完后自动接着录下一首，每首单独导出成一个 MP3**；连录期间不会在每首结束时暂停播放器，播放停止或歌单放完即结束 |
| 内录系统声音 | WASAPI 环回（Loopback）直接采集系统播放的声音，**不依赖声卡"立体声混音"**，音质无损（数字采集） |
| 自动停止 | 播放到曲末 / 换歌 / 播放器停止，任一条件命中即自动停止录制并完成编码 |
| **过短录音确认** | 录制被手动暂停/打断且**时长不足 10 秒**时弹窗询问「是否仍要导出这段音频？」——选是正常导出，选否直接删掉文件 |
| 结束后自动暂停播放 | 录制结束后自动暂停播放器——尤其是自动停止时播放器已切到下一首，会在换歌瞬间立刻暂停，不会继续播下去（可关闭） |
| 自动命名导出 | 以 **`歌曲名-歌手`** 命名 MP3（如 `人是猫-张卡斯.mp3`；读不到歌手时只用歌曲名），自动写入 ID3 标签（标题=纯歌曲名、歌手、专辑），重名自动加序号 `(2)` |
| 其他 | 可选录音设备、128/192/256/320 kbps 码率、录完自动打开文件夹、设置持久化、日志排错 |

## 二、使用步骤

> **绿色版直接使用**：双击 `MusicRecorder.exe`（单文件，自带 .NET 运行时，约 70 MB，无需安装任何依赖）。

1. 打开 QQ音乐 / 网易云音乐 / 酷狗音乐，播放任意一首歌（暂停状态也可以，会自动开始播放）。
2. 打开 `MusicRecorder.exe`，在**上方**选择导出路径（默认：`音乐\MusicRecorder`）。
3. 点击**下方大按钮「开始录制」**。
4. 工具会自动把这首歌倒回开头并开始录制；**歌曲播放结束后自动停止并暂停播放器**，在导出目录生成 `歌曲名-歌手.mp3`。

录制过程中按钮会变成红色的「■ 停止并保存」，想提前结束可以手动点击或直接关闭窗口（关闭时会询问是否保存）。

> **想完全不用手点？** 勾选「**自动录制**」：在播放器里点播放，工具就会自动把歌曲倒回开头并开始录制这一首；
> 录完自动暂停播放器，下次再点播放就录下一首。（勾选时若已经在播放，会立即开始录制这一首。）
>
> **想把一整张歌单都录下来？** 勾选「**自动录制整张歌单**」：点播放开始录，每首放完自动接着录下一首，
> 每首歌单独导出一个 MP3；连录期间不会暂停播放器（所以「结束后自动暂停播放」在该模式下自动置灰）。

## 三、工作原理

```
                    ┌─────────────────────────────────────────┐
   音乐软件 ───────▶│ Windows 媒体会话 (SMTC / WinRT)          │
 (QQ音乐/网易云…)    │  · 歌曲名 / 歌手 / 进度 / 播放状态        │──▶ 读取与播放控制
                    │  · 定位到开头 / 上下一曲 / 暂停           │
                    └─────────────────────────────────────────┘
                    ┌─────────────────────────────────────────┐
   系统声音输出 ────▶│ WASAPI 环回采集 (NAudio)                 │
                    │  32bit float 48k ─▶ 16bit PCM ─▶ LAME   │──▶ 歌曲名-歌手.mp3
                    └─────────────────────────────────────────┘
```

**"从头播放"的三重方案**（按播放器**实际声明的能力**选择，避免"以为成功其实没动"）：

1. **系统媒体控制定位**：仅当播放器声明支持定位（`IsPlaybackPositionEnabled=true`）时才使用 `TryChangePlaybackPositionAsync(0)`，并用播放进度复核（PotPlayer 已验证可用）。
2. **「下一曲 + 上一曲」**：先切到下一首、再切回本首——**被切回的歌一定从 0:00 开始**，并用歌名变化验证确实切回了同一首歌。这是 QQ音乐 / 网易云音乐 这类**不提供进度、也不支持定位**的播放器唯一可靠的办法（QQ音乐 实测生效，并用音频指纹验证过起点一致）。
3. **系统媒体键**兜底（`VK_MEDIA_PREV_TRACK`）。

> ⚠️ 关键坑：QQ音乐 的时间轴恒为 0，而且 `TryChangePlaybackPositionAsync` **会返回 True 但什么都不做**（"假装成功"）。所以进度是否可信、能否定位，一律以播放器**声明的能力**为准，不能只看返回值和进度值。

**"自动停止"的判定条件**：播放进度到达曲末 0.4 秒内 / 检测到换歌（歌曲名变化）/ 播放状态离开"播放中"（停止、暂停、播放器退出）/ 进度明显回退 / 超长保护（20 分钟）。

**「自动录制」的触发条件**：
- 「自动录制（单首）」：勾选后工具每 0.25 秒检查一次会话状态，只在**播放状态由"非播放"变为"播放"**的那一刻触发一次（一次播放只录一首），播放停止/暂停后重新武装——所以录制结束时"我们主动暂停播放器"不会被误判成新的播放而反复开录。**不追踪换歌**。
- 「自动录制整张歌单」：在上一条件之外还跟踪**换歌**（歌曲标识变化）——上一首录完后自动接着录下一首，每首单独导出。因为新歌此时已经播了一小段，换歌触发时会**强制把新歌倒回 0:00**（靠"位置判据"会误判成"已在开头"）。该模式不会在每首结束时暂停播放器，否则无法连录；「结束后自动暂停播放」会被自动置灰。

自动录制模式**不弹任何对话框**（失败只写状态栏与日志），避免打断听歌。

**「过短录音确认」**：录制因**手动暂停或打断**结束（手动停止 / 播放器被暂停停止 / 采集中断）且**时长不足 10 秒**时，会弹窗询问「是否仍要导出这段音频？」——选「是」正常导出，选「否」直接删除已生成的音频文件、不更新「上次导出」。正常播完（曲末 / 换歌）结束的短音频不会询问。

**进度显示**：能拿到进度的播放器显示 `mm:ss / mm:ss` 与百分比进度条；QQ音乐 / 网易云音乐 不提供总时长，此时显示**已录制时长**（因为工具总是从 0:00 开始录，录制时长＝歌曲进度），并在状态栏说明将在换歌/停止时自动结束。

## 五、常见问题

**Q：录制的声音包含其他程序的声音吗？**
会。环回采集的是系统**总输出**，录制期间的通知音、其他视频声音都会被一并录进去。录制时请避免播放其他声音。

**Q：QQ音乐 / 网易云音乐 的进度条一直是 0？**
这两家的媒体会话**不提供播放进度与总时长**（实测：QQ音乐 的 `位置/起点/终点/最小定位` 全部为 0，`更新时间` 是未更新的 08:00:00，且其窗口为腾讯自绘 UI、UI 自动化树子元素数为 0）。这是播放器自身的实现问题——它不通过系统媒体接口暴露这些数据，任何工具都拿不到。因此界面改为显示**已录制时长**：由于工具总是从歌曲 0:00 开始录，**录制时长就是歌曲进度**。结尾判断依靠**换歌 / 停止播放**，正常播放列表下能准确停止；若开启「单曲循环」需手动点停止（有 20 分钟超长保护兜底）。

**Q：怎么确认"真的从头播放"了？**
连续录两次同一首歌，然后运行：

```powershell
MusicRecorder.exe --compare --a="第一次.mp3" --b="第二次.mp3"
```

工具会对两段音频的包络做互相关扫描，**最佳匹配出现在偏移 0 ms 且相关度高**就说明两次都从歌曲开头开始（QQ音乐 实测偏移 0 ms / 相关度 0.817，不同歌曲对照组最高只有 0.105）。

**Q：勾了「自动录制」，在播放器里点播放却没开始录？**
1. 确认「目标播放器」选的是你正在用的那个（默认"自动选择"会优先挑它认识且正在播放的播放器；如果你用的是小众播放器或网页播放器，建议在下拉框里手动指定）。
2. 自动录制只在"播放状态由停止/暂停变为播放"的那一刻触发：如果这首歌**已经在播放**，请先暂停再点播放；勾选「自动录制」的瞬间若正在播放，会立即开始录制。
3. 若关闭了「结束后自动暂停播放」，播放器自动连播下一首时不会再触发（没有新的"点播放"动作）——想连录请用「自动录制整张歌单」。
4. 失败原因会写在状态栏与日志里（`%LOCALAPPDATA%\MusicRecorder\logs\`）。

**Q：怎么把一整张歌单自动录下来（每首一个文件）？**
勾选「自动录制整张歌单」→ 在播放器里从头播放这张歌单即可。工具会在每首放完后自动接着录下一首，
以歌曲名分别导出（重名自动加序号）。期间**不要**开启「结束后自动暂停播放」（该模式下它本来也会被置灰）。
播放停止或歌单放完即结束；若某首歌放完时判定为"被打断"且不足 10 秒，仍会按规则弹窗询问是否导出。

**Q：弹窗说"录制时长过短（音频可能被手动暂停或打断）"，是什么意思？**
录制是被**手动暂停/打断**结束的（你自己点了停止、或在播放器里按了暂停、或采集流中断），而且总共不到 10 秒。
选「是」照常导出；选「否」这个文件会被直接删除（导出目录里不会留下）。正常播完的短音频不会弹这个窗。

**Q：点击开始后提示"无法自动把进度倒回开头"？**
说明该播放器既不能定位进度、也无法通过切歌返回（例如播放列表里只有这一首、且不接受切歌指令）。此时工具会从当前位置开始录制，建议手动切到该歌曲开头后重新点击录制。

**Q：录制结束后音乐还在响？**
工具默认会在录制结束时**自动暂停播放器**（界面上的「结束后自动暂停播放」）。自动停止时若播放器已经切到下一首，会在换歌的瞬间立刻暂停，下一首基本不会被录进去也不会继续播。若该播放器不接受系统暂停指令，状态栏会提示"未能自动暂停播放器，请手动暂停"。

**Q：VIP / 加密格式的歌曲能录吗？**
能录到**声音**（MP3 是数字环回采集，与解码格式无关），但请遵守音乐平台的版权与会员协议，仅用于个人合法用途（如离线自听、个人收藏）。请勿传播或商用。

**Q：录制失败 / 没有声音？**
1. 检查系统是否静音、音量是否为 0（工具启动时日志会记录默认设备音量）。
2. 界面「录音设备」里换成**正在出声的那个设备**（例如插着耳机时就选耳机的"扬声器"）。
3. 日志位于 `%LOCALAPPDATA%\MusicRecorder\logs\`。

## 六、构建与自检

需要 .NET 8 SDK（仅开发时需要；发布出的 exe 自带运行时，用户无需安装任何东西）。

```powershell
# 构建
dotnet build MusicRecorder.csproj -c Release

# 或使用脚本
pwsh -File build.ps1            # 构建
pwsh -File build.ps1 -Publish   # 发布单文件绿色版到 dist\
pwsh -File build.ps1 -Package   # 发布并打包成可分发 zip 到 release\

# 32 位（x86）版本：加 -RuntimeIdentifier win-x86
pwsh -File build.ps1 -Package -RuntimeIdentifier win-x86
```

等价的手工发布命令（`-r` 换成 `win-x86` 即为 32 位版本）：

```powershell
dotnet publish MusicRecorder.csproj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true -o dist
```

内置自检 / 诊断命令（结果同时写入 `%TEMP%\MusicRecorder-selftest.txt`）：

```powershell
MusicRecorder.exe --selftest --seconds=8 --tone   # 检查 SMTC/设备，并边放测试音边录 8 秒
MusicRecorder.exe --e2e --seconds=150             # 端到端：对当前正在播放的歌曲走完整录制流程
MusicRecorder.exe --diag --play --seconds=6       # 诊断：导出播放器的媒体会话能力/时间轴，并实测定位与切歌是否真的生效
MusicRecorder.exe --compare --a=1.mp3 --b=2.mp3   # 对比两段录音是否都从歌曲开头开始（音频指纹）
MusicRecorder.exe --gentest --seconds=25          # 生成 25 秒测试歌曲（带 ID3 标签）
MusicRecorder.exe --fakeplayer --file=<mp3路径>    # 启动一个会注册媒体会话的模拟播放器
MusicRecorder.exe --fakeplayer --files="a.mp3;b.mp3" --titles="一;二"   # 多首连播，用于验证"歌单连录"
MusicRecorder.exe --pause                         # 暂停当前播放器（可加 --app=<会话标识> 精确指定）
```

## 七、工程结构

```
MusicRecorder/
├─ MusicRecorder.csproj          .NET 8 WPF 工程（net8.0-windows10.0.19041.0）
├─ MainWindow.xaml(.cs)          界面：上方导出路径 / 中部歌曲信息 / 下方开始录制按钮
├─ App.xaml(.cs)                 启动、单实例、命令行自检入口、全局异常处理
├─ SelfTest.cs                   自检与开发测试工具（--selftest/--e2e/--diag/--compare/--gentest/--fakeplayer/--pause）
├─ Core/
│  ├─ MediaSessionService.cs     SMTC 媒体会话：歌曲信息读取 + 播放/定位/切歌/暂停控制
│  ├─ RecorderEngine.cs          录制流程编排：开始 / 轮询结尾判定 / 停止 / 命名导出
│  ├─ AudioRecorder.cs           WASAPI 环回采集 → 16bit PCM → MP3（LAME，兜底 MediaFoundation）
│  ├─ MediaKeySender.cs          系统媒体键兜底
│  ├─ WindowProbe.cs             窗口标题兜底识别（无媒体会话时）
│  ├─ Id3Writer.cs               ID3v2.3 标签写入（兜底编码路径）
│  ├─ AppSettings.cs             配置持久化（%APPDATA%\MusicRecorder\settings.json）
│  └─ Log.cs                     日志（%LOCALAPPDATA%\MusicRecorder\logs）
├─ 使用说明.txt                   面向使用者的说明（随发布包分发）
├─ CHANGELOG.md                  版本变更记录
└─ build.ps1                     构建 / 发布 / 打包脚本
```
